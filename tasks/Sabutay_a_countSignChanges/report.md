## 1. Введение

Часто при обработке сигналов, статистических рядов или телеметрии нужно отслеживать, как часто последовательность меняет знак между соседними элементами. Это позволяет найти числа переходов через ноль и сопоставить изменения характеристик системы. Цель работы — реализовать и сравнить последовательную (SEQ) и параллельную (MPI) версии алгоритма подсчёта смен знаков, протестировать их корректность и оценить производительность на практических данных.

## 2. Постановка задачи

### 2.1 Формальное определение

Пусть задан вектор `V = [x1, x2, ..., xn]`. Требуется посчитать количество пар `(xi, xi+1)`, в которых оба элемента ненулевые и имеют разные знаки. Формально, пара учитывается, если `sign(xi) ≠ sign(xi+1)` и `xi * xi+1 < 0`.

### 2.2 Входные и выходные данные

- **Вход**: `std::vector<int>` либо эквивалентный набор значений, где `n ≥ 2`.
- **Выход**: `int`, количество чередований знака между соседними элементами.

### 2.3 Особые случаи

- Нулевые значения пропускаются: пара, содержащая хотя бы один ноль, не считается.
- Векторы длиной 0 или 1 возвращают 0 чередований.
- Если все элементы одного знака, результат также равен 0.
- Значение, вычисленное в SEQ и MPI версиях, должно совпадать.

### 2.4 Примеры

- `[1, -1, 1, -1]` → пары `(1, -1), (-1, 1), (1, -1)` → 3 чередования.
- `[1, 0, -1, 2, -2]` → пары `(1, 0), (0, -1), (-1, 2), (2, -2)` → учитываются только две смены знака → 2.
- `[1, -1, 1, 1, 2, -3]` → пары `(1, -1), (-1, 1), (1, 1), (1, 2), (2, -3)` → 3 чередования.

## 3. Базовый/последовательный алгоритм

Последовательная версия проходит по вектору слева направо и рассматривает каждую пару соседних элементов.

1. **Инициализация** — счётчик `alternations_count = 0`.
2. **Граничные условия** — если размер `< 2`, возвращаем 0.
3. **Сканирование пары** — для каждого `i` сравниваем `current = input[i]` и `next = input[i+1]`.
4. **Условие смены знака** — учитываем пару, если оба значения ненулевые и имеют противоположные знаки.
5. **Возврат результата** — сохраняем количество чередований в `GetOutput()`.

Алгоритмическая сложность равна `O(n)` по числу элементов. Реализация расположена в `seq/src/ops_seq.cpp` и точно следует описанным шагам, без дополнительной памяти помимо входного вектора.

## 4. Схема распараллеливания алгоритма

### 4.1 Распределение данных

- Рассчитываем общее число пар `pairs_count = n - 1`.
- Длина блока `pairs_per_process = pairs_count / world_size`.
- Остаток `remainder = pairs_count % world_size` распределяется между первыми процессами для балансировки по одному элементу сверху.

### 4.2 Схема коммуникации

Каждый процесс читает доступный входной вектор, считает свою порцию пар и отправляет локальный результат на процесс 0. Координатор суммирует данные и рассылает итог всем участникам.

### 4.3 Роли процессов

- **Ранг 0** — вычисляет свою часть, собирает частичные суммы через `MPI_Recv`, формирует итог и рассылает его через `MPI_Send`.
- **Остальные ранги** — считают локальные чередования и отправляют результат координатору.

### 4.4 Синхронизация

- `MPI_Bcast` используется для рассылки финального ответа.
- `MPI_Barrier` в начале и конце `RunImpl` гарантирует, что все процессы завершили вычисления перед выходом.

### 4.5 MPI-алгоритм (кратко)

1. Получаем `world_size` и `world_rank`.
2. При `n < 2` сразу возвращаем 0.
3. Вычисляем отрезок `[start_pair, end_pair)` для текущего ранга.
4. Подсчитываем локальные чередования в своей области.
5. Ранг 0 собирает результаты и рассылает финальный ответ.

### 5.3 Реализация SEQ

Основная логика находится в `seq/src/ops_seq.cpp` и выглядит так:

```cpp
bool SabutayACountSignChangesSEQ::RunImpl() {
  std::vector<InType> vec;
  vec.reserve(GetInput() + 1);

  for (InType i = 0; i <= GetInput(); i++) {
    vec.push_back((i % 2 == 0) ? (i + 1) : -(i + 1));
  }

  InType sign_changes = 0;
  for (size_t i = 0; i < vec.size() - 1; i++) {
    if ((vec[i] > 0 && vec[i + 1] < 0) || (vec[i] < 0 && vec[i + 1] > 0)) {
      sign_changes++;
    }
  }

  GetOutput() = sign_changes;
  return true;
}
```

Вектор специально создаётся с чередованием знаков, после чего одна линейная проходка считает количество смен.

### 5.4 Реализация MPI

Файл `mpi/src/ops_mpi.cpp` содержит распределённую версию:

```cpp
bool SabutayACountSignChangesMPI::RunImpl() {
  int rank = 0, size = 1;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);

  if (GetInput() == 0) {
    GetOutput() = 0;
    MPI_Barrier(MPI_COMM_WORLD);
    return true;
  }

  std::vector<InType> full_vec(GetInput() + 1);
  for (InType i = 0; i <= GetInput(); i++) {
    full_vec[i] = (i % 2 == 0) ? (i + 1) : -(i + 1);
  }

  const InType pairs_count = GetInput();
  const InType pairs_per_process = (pairs_count + size - 1) / size;
  const InType start_pair = rank * pairs_per_process;
  const InType end_pair = std::min(start_pair + pairs_per_process, pairs_count);

  InType local_count = 0;
  for (InType i = start_pair; i < end_pair; i++) {
    if ((full_vec[i] > 0 && full_vec[i + 1] < 0) || (full_vec[i] < 0 && full_vec[i + 1] > 0)) {
      local_count++;
    }
  }

  InType total_count = 0;
  MPI_Reduce(&local_count, &total_count, 1, MPI_INT, MPI_SUM, 0, MPI_COMM_WORLD);
  MPI_Bcast(&total_count, 1, MPI_INT, 0, MPI_COMM_WORLD);

  GetOutput() = total_count;
  return true;
}
```

Каждый процесс обрабатывает свой диапазон пар, после чего суммарное значение собирается на ранге 0 и рассылается обратно всем участникам.

**Интерпретация**:

- Для коротких входов накладные расходы MPI (`MPI_Reduce`, `MPI_Bcast`, пересылка пограничных значений) превышают полезную работу. Поэтому последовательная версия быстрее.
- С ростом длины вектора (10⁶ и более) ожидается, что доля вычислений станет доминирующей и MPI-версия начнёт опережать SEQ.
- Pipeline-режим даёт ещё более заметную деградацию из‑за необходимости прогонять весь жизненный цикл задачи в каждом процессе.
