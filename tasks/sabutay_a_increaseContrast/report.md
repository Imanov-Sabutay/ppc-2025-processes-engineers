## 1. Introduction

Задача заключается в увеличении контраста изображений путем нормализации значений яркости пикселей. Контраст изображения увеличивается путем масштабирования значений яркости от минимального до максимального значения в диапазон [0, 255]. Это позволяет улучшить визуальное качество изображений с низким контрастом.

## 2. Problem Statement

**Входные данные:** 
- Набор изображений (pic_0.jpeg, pic_1.jpg, pic_2.jpg, pic_3.jpg)
- Целое число (используется для валидации)

**Выходные данные:**
- Целое число (равное входному значению)

**Алгоритм:**
1. Загрузить каждое изображение
2. Преобразовать RGB в оттенки серого по формуле: `gray = 0.299*R + 0.587*G + 0.114*B`
3. Найти минимальное и максимальное значение яркости
4. Применить линейное масштабирование: `new_gray = (gray - min) * 255 / (max - min)`


**Ограничения:**
- Изображения должны быть квадратными (width == height)
- Если изображение не загружается, оно пропускается

## 3. Baseline Algorithm (Sequential)

Последовательный алгоритм:

```cpp
for each image_file:
    load image
    convert RGB to grayscale
    find min and max grayscale values
    if max > min:
        scale = 255.0 / (max - min)
        for each pixel:
            new_gray = (gray - min) * scale
```

Алгоритм обрабатывает каждое изображение последовательно, вычисляя минимальное и максимальное значение яркости, а затем применяя линейное масштабирование для увеличения контраста.

## 4. Parallelization Scheme

### MPI версия:

**Распределение данных:**
- Процесс 0 загружает изображение и передает его всем процессам через `MPI_Bcast`
- Строки изображения распределяются между процессами:
  - Первые `remainder` процессов получают `rows_per_process + 1` строк
  - Остальные процессы получают `rows_per_process` строк
  - Формула: `start_row = rank * rows_per_process + min(rank, remainder)`

**Коммуникационный паттерн:**
1. `MPI_Bcast` для передачи размеров изображения (width, height, channels) - синхронизирует все процессы
2. `MPI_Bcast` для передачи данных изображения от процесса 0 ко всем
3. `MPI_Allreduce` для нахождения глобального минимума (MPI_MIN) 
4. `MPI_Allreduce` для нахождения глобального максимума (MPI_MAX)
5. **`MPI_Barrier` в конце `RunImpl()` - критически важно для синхронизации всех процессов**

**Обработка граничных случаев:**
- Если процесс не получает строк (при height < size), он все равно участвует во всех коллективных операциях
- Если изображение не загружается, все процессы синхронно получают размеры (0,0,0) через `MPI_Bcast` и пропускают его вместе
- Все процессы всегда находятся в одной итерации цикла по изображениям

**Роли процессов:**
- Rank 0: загрузка изображений, координация вычислений
- Все процессы: обработка своих строк, участие в редукциях

## 5. Implementation Details

**Структура кода:**
- `common/include/common.hpp` - общие типы и базовый класс
- `seq/src/ops_seq.cpp` - последовательная реализация
- `mpi/src/ops_mpi.cpp` - MPI реализация
- `tests/functional/main.cpp` - функциональные тесты
- `tests/performance/main.cpp` - тесты производительности

**Важные детали реализации:**
- Использование библиотеки `stb_image` для загрузки изображений (только на rank 0)
- Преобразование RGB в оттенки серого: `gray = 0.299*R + 0.587*G + 0.114*B`
- Все процессы синхронно пропускают невалидные изображения через `MPI_Bcast` размеров
- Корректное распределение строк с учетом остатка от деления
- Использование `MPI_Allreduce` для эффективной редукции и распространения min/max
- **Критично важно: `MPI_Barrier` в конце `RunImpl()` по паттерну `example_processes`**
- Процессы с нулевым количеством строк корректно участвуют в `MPI_Allreduce`

**Управление памятью:**
- Изображения загружаются только на процессе 0 с помощью `stbi_load`
- Данные передаются через `MPI_Bcast` на все процессы
- Каждый процесс хранит полную копию изображения для обработки своих строк
- Память освобождается автоматически (`std::vector`, `stbi_image_free`)
