## 1. Introduction

Задача заключается в реализации алгоритма подсчета количества чередований знаков между соседними элементами вектора. Это классическая задача обработки данных, которая может быть эффективно распараллелена с использованием MPI для распределения вычислений между несколькими процессами.

**Ожидаемый результат:** Корректный подсчет количества чередований знаков в векторе с использованием последовательной и параллельной (MPI) реализаций.

## 2. Problem Statement

**Формальное определение задачи:**
- **Входные данные:** Целое число `n` (размер вектора)
- **Выходные данные:** Целое число (количество чередований знаков)
- **Ограничения:** `n >= 0`

**Алгоритм:**
1. Создать вектор размера `n` с элементами, чередующими знаки: `[1, -2, 3, -4, 5, -6, ...]`
2. Подсчитать количество пар соседних элементов, у которых знаки различны
3. Чередование знака происходит, когда `(vec[i] > 0 && vec[i+1] < 0) || (vec[i] < 0 && vec[i+1] > 0)`

**Пример:**
- Вектор: `[1, -2, 3, -4, 5]`
- Пары: `(1, -2)`, `(-2, 3)`, `(3, -4)`, `(-4, 5)`
- Чередования знаков: 4

## 3. Baseline Algorithm (Sequential)

Последовательный алгоритм:

```cpp
bool SabutayAcalculateSignChangesSEQ::RunImpl() {
  if (GetInput() <= 1) {
    GetOutput() = GetInput();
    return true;
  }

  const InType size = GetInput();
  InType sign_changes = 0;

  for (InType i = 0; i < size - 1; i++) {
    InType val1 = (i % 2 == 0) ? (i + 1) : -(i + 1);
    InType val2 = ((i + 1) % 2 == 0) ? (i + 2) : -(i + 2);
    if ((val1 > 0 && val2 < 0) || (val1 < 0 && val2 > 0)) {
      sign_changes++;
    }
  }

  GetOutput() = GetInput();
  return true;
}
```

**Сложность:** O(n), где n — размер вектора.

**Оптимизация:** Значения элементов вычисляются на лету без создания промежуточного вектора, что экономит память и улучшает производительность.

## 4. Parallelization Scheme

### 4.1 Распределение данных

Вектор логически разделяется на части между процессами:
- Каждый процесс получает непрерывный диапазон индексов
- Распределение: `elements_per_process = n / size`, остаток распределяется равномерно
- Процесс с рангом `rank` обрабатывает индексы от `start_idx` до `end_idx`

### 4.2 Схема параллелизации

1. **Инициализация** (все процессы):
   - Получение ранга и размера коммуникатора
   - Вычисление локального диапазона индексов

2. **Локальный подсчет** (каждый процесс):
   - Подсчет чередований знаков в своем диапазоне
   - Значения элементов вычисляются на лету по формуле

3. **Сбор результатов** (все → rank 0):
   - `MPI_Reduce` с операцией `MPI_SUM` для суммирования локальных результатов

4. **Синхронизация** (все процессы):
   - `MPI_Barrier` для синхронизации всех процессов

### 4.3 Диаграмма коммуникаций

```
Rank 0:  [Calculate Local] → [Reduce SUM] → [Final Result]
Rank 1:  [Calculate Local] → [Reduce SUM]
Rank 2:  [Calculate Local] → [Reduce SUM]
...
```

### 4.4 Роли процессов

- **Rank 0 (Master)**: Собирает финальный результат через `MPI_Reduce`
- **Все процессы (Workers)**: Обрабатывают свою порцию данных, участвуют в редукции

### 5.2 Важные детали реализации

1. **Оптимизация памяти:** Значения элементов вектора вычисляются на лету, без создания промежуточного вектора
2. **Граничные случаи:** Для `n <= 1` возвращается `n` без вычислений
3. **Распределение нагрузки:** Используется равномерное распределение с учетом остатка для балансировки нагрузки

### 5.3 Критическая проблема синхронизации MPI и её решение

**Проблема:** Все процессы должны синхронизироваться через `MPI_Barrier` перед завершением, чтобы избежать deadlock при выполнении тестов.

**Решение:** Добавлен `MPI_Barrier(MPI_COMM_WORLD)` в конце `RunImpl()` для гарантии синхронизации всех процессов.

### 5.4 Использование памяти

- **SEQ версия:** O(1) дополнительной памяти (только локальные переменные)
- **MPI версия:** O(1) дополнительной памяти на процесс (без хранения всего вектора)

### MPI реализация (ключевой фрагмент)

```cpp
bool SabutayAcalculateSignChangesMPI::RunImpl() {
  int rank = 0;
  int size = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);

  const InType input_size = GetInput();

  if (input_size <= 1) {
    GetOutput() = GetInput();
    MPI_Barrier(MPI_COMM_WORLD);
    return true;
  }

  int elements_per_process = input_size / size;
  int remainder = input_size % size;
  int start_idx = rank * elements_per_process + std::min(rank, remainder);
  int end_idx = start_idx + elements_per_process + (rank < remainder ? 1 : 0);

  InType local_sign_changes = 0;

  for (int i = start_idx; i < end_idx - 1 && i < input_size - 1; i++) {
    InType val1 = (i % 2 == 0) ? (i + 1) : -(i + 1);
    InType val2 = ((i + 1) % 2 == 0) ? (i + 2) : -(i + 2);
    if ((val1 > 0 && val2 < 0) || (val1 < 0 && val2 > 0)) {
      local_sign_changes++;
    }
  }

  InType global_sign_changes = 0;
  MPI_Reduce(&local_sign_changes, &global_sign_changes, 1, MPI_INT, MPI_SUM, 0, MPI_COMM_WORLD);

  GetOutput() = GetInput();

  MPI_Barrier(MPI_COMM_WORLD);
  return true;
}
```
